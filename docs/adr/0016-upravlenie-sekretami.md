# ADR-0016: GitHub Environment как источник правды по секретам

**Дата:** 2026-07-30 · **Статус:** принято

## Контекст

Секреты нужны в двух разных моментах времени, и это разные задачи:

1. **Во время деплоя** — SSH-ключ, адрес сервера, токен бота. Живут в GitHub, используются раз.
2. **Во время работы** — пароль БД, `SECRET_KEY`, SMTP. Нужны контейнерам при **каждом**
   старте, включая перезагрузку сервера, когда GitHub не участвует вообще.

Первая версия runbook предлагала редактировать `.env` на сервере руками через `nano`.
Это давало три проблемы: нет истории изменений, нет процедуры ротации, и при переезде
на новый сервер всё повторяется по памяти.

## Решение

Единственный источник правды — **GitHub Environment `production`**. Джоба деплоя
рендерит `.env` из секретов, кладёт на сервер с правами `600` и атомарно подменяет.
Руками `.env` не редактируется никогда.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Хранить только в GitHub Secrets, без файла на сервере | Не работает физически: после перезагрузки сервера Docker поднимает контейнеры без переменных, и сайт лежит до следующего пуша |
| Редактировать `.env` на сервере вручную | Нет истории, нет ротации, невоспроизводимо при переезде |
| SOPS + age: секреты зашифрованы прямо в репозитории | Лучше по аудиту и версионированию, но добавляет инструмент и ключ, который сам надо где-то хранить. Разумный апгрейд, когда секретов станет больше двадцати |
| HashiCorp Vault / Infisical | Отдельный сервис с своей доступностью и памятью. На 4 ГБ и один сайт — абсурд |

## Последствия

**Стало лучше:** ротация любого секрета — одна команда `gh secret set` плюс повторный
запуск пайплайна. Новый сервер поднимается с нуля без ручной работы. Значения
маскируются в логах Actions автоматически.

**Цена, которую платим:** на сервере всё равно лежит `.env` открытым текстом — Docker
Compose иначе не умеет, и это неизбежно при любом варианте кроме монтирования секретов
рантаймом. Защита здесь — права `600`, non-root контейнеры и закрытый SSH, а не шифрование.

**Отдельная мина:** `POSTGRES_PASSWORD` после первого деплоя нельзя поменять просто
ротацией секрета — пароль уже записан внутрь базы. Смена требует `ALTER USER` в Postgres
в том же окне, иначе приложение перестанет подключаться. Вынесено в runbook отдельным
предупреждением.
