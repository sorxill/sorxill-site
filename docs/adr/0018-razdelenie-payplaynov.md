# ADR-0018: проверки на коммит, сборка и деплой на тег

**Дата:** 2026-07-30 · **Статус:** принято · **Заменяет часть** ADR-0003

## Контекст

Первая версия сводила проверки, сборку образов, скан и деплой в один `pipeline.yml`
на каждый push в main. Практика показала три проблемы:

1. **7 минут ожидания на каждый коммит**, включая правку опечатки в README.
2. **Каждый деплой автоматический.** На personal-сайте нет причин выкатывать
   прод при каждом коммите — это лишает контроля над тем, что видят люди.
3. **Trivy блокировал всё** из-за CVE в транзитивных зависимостях и в npm,
   вшитом в базовый образ. То, что мы не контролируем, останавливало работу.

## Решение

Два workflow с разными триггерами:

| | `checks.yml` | `release.yml` |
|---|---|---|
| Когда | каждый push и PR | тег `v*` или запуск вручную |
| Что | ruff, mypy, границы слоёв, pytest, tsc, eslint, vitest, build, size-limit, gitleaks | сборка образов, Trivy, push в GHCR, деплой на сервер |
| Сколько | 2-3 минуты | 7-10 минут |

Тег создаёт `release-please` при мерже релизного PR, поэтому релиз остаётся
одним кликом, но происходит когда вы решили, а не когда исправили опечатку.

Trivy переведён в неблокирующий режим: `exit-code: 0`, результат уходит в
Security → Code scanning в формате SARIF.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Оставить всё в одном пайплайне | Ожидание на каждый коммит, автодеплой без контроля |
| Деплой по кнопке `workflow_dispatch`, без тегов | Теряется связь «версия ↔ что задеплоено». При откате непонятно, куда возвращаться |
| Оставить Trivy блокирующим | CVE в npm базового образа не чинится нашим кодом. Блокирующий скан, который нельзя удовлетворить, отключают через месяц — и тогда скана нет вообще |
| Отключить Trivy | Тогда мы не узнаем про уязвимость в **своих** зависимостях, а это как раз то, что чинится |

## Последствия

**Стало лучше:** обратная связь по коду за 2-3 минуты. Деплой осознанный.
Находки безопасности видны в одном месте и накапливаются, а не теряются в логах.

**Цена:** между мержем и появлением на проде теперь есть шаг. Забыв его сделать,
можно неделю думать, что изменения на сайте, а они только в main. Смягчение —
`release-please` держит открытым релизный PR со списком неотгруженного.

**Что осталось нерешённым:** Trivy теперь только сообщает. Нужна привычка раз
в месяц заглядывать в Security → Code scanning, иначе неблокирующий скан
превращается в декоративный. Вынесено в runbook по зависимостям.
