# ADR-0022: PostCSS-конфиг обязателен, токены объявляются через `@theme static`

**Дата:** 2026-07-31 · **Статус:** принято

## Контекст

M1 закрыт с зелёным CI, но на проде не работали стили. Разбор показал две
разные проблемы, которые накладывались друг на друга и маскировали одна другую.

**Первая.** В `apps/web` не было `postcss.config.*`. Tailwind v4 подключается к
Next именно через PostCSS-плагин; без конфига этап обработки CSS не выполняется
вообще. Директива `@theme` доезжала до браузера сырой:

```
@theme{ --color-paper:#e7ebe7; ... }[data-theme=dark]{ --color-paper:#0e1417; ... }
html{background:var(--color-paper)}
```

Весь прод-CSS занимал 1846 байт. Браузер не знает `@theme` и отбрасывает блок
целиком, поэтому **в светлой теме не был определён ни один токен, а в тёмной —
все**: `[data-theme="dark"]` это обычное правило, оно пережило отсутствие
компиляции. Отсюда обманчивый симптом — «тёмная тема работает, светлая нет»,
который выглядит как ошибка в теме, а не как отсутствие сборки.

**Вторая.** После добавления конфига Tailwind v4 выносит в `:root` только те
токены, которые где-то использованы. Проверка собранного бандла: `--color-line`,
`--color-surface`, `--color-track`, `--text-step-5`, `--spacing-section`
отсутствовали в `:root`, но присутствовали в `[data-theme="dark"]` — потому что
тёмный блок написан руками и перечисляет всё. Макет `docs/03-homepage-mockup.html`
построен на прямых `var(--color-line)` в рукописном CSS, а не на утилитах
Tailwind, поэтому после переноса светлая тема сломалась бы снова — тише и
позже.

## Решение

Добавить `apps/web/postcss.config.mjs` с плагином `@tailwindcss/postcss`
и объявлять токены через `@theme static`, а не `@theme`.

Заодно убран второй `@import "tailwindcss"` из `tokens.css`: импорт остаётся
ровно один, в `globals.css`. Дублирования в выводе он не давал (Tailwind
дедуплицирует), но два входа в один и тот же слой — лишний источник путаницы.

## Альтернативы

| Вариант | Почему не он |
|---|---|
| Оставить `@theme` и авторить всё утилитами Tailwind | Тогда макет придётся переписывать, а не переносить. Фаски, насечки на полосах опыта и орбита в героe утилитами не выражаются — это рукописный CSS, и он будет читать `var()` напрямую |
| Оставить `@theme` и перечислять светлые значения в `:root` руками, как сделано для тёмной темы | Два списка одних и тех же токенов, которые обязаны не разъезжаться. Ровно тот дубликат, ради устранения которого токены и вводились |
| Отказаться от Tailwind, оставить голый CSS с `:root` | Честный вариант: макет всё равно почти целиком рукописный, а от Tailwind используется preflight и десяток утилит. Но LLD §5 уже описывает `@theme` как источник правды, и отказ тянет за собой правку документов и потерю утилит на будущих формах в M3. Отложено, не отвергнуто |
| Убрать `@import "tailwindcss"` из `globals.css`, оставив его в `tokens.css` | Симметрично, но тогда точка входа в стили не совпадает с точкой входа Next. Читать сложнее |

## Последствия

**Стало лучше:** светлая тема наконец существует. Собранный CSS вырос с 1846
байт (нерабочих) до 5733 байт (рабочих). Токены определены полностью и в
светлой, и в тёмной теме, так что рукописный CSS макета можно переносить
как есть.

**Цена:** `static` отключает tree-shaking токенов. Замер — 5733 байта против
4899 без `static`, то есть **+834 байта** за все неиспользуемые токены. Цифра
будет расти по мере добавления токенов и не будет падать при их выходе из
употребления. Мёртвые токены придётся удалять из `tokens.css` руками — сборка
о них больше не сообщит.

Порог, при котором решение стоит пересмотреть: если `tokens.css` разрастётся
настолько, что неиспользуемая часть перевалит за ~3 КБ. При текущем размере
файла это далеко.

**Что осталось нерешённым:** ни одна проверка в CI не заметила, что стилей нет.
`next build` был зелёным, `tsc`, `eslint` и `vitest` тоже, smoke-тест после
деплоя проверяет код ответа `/`, а не содержимое CSS. Гейт для фронтенда —
Lighthouse CI, порог покрытия, проверка на непустой вычисленный фон — заводится
отдельной задачей в M2 и должен появиться **до** первого компонента, иначе
следующая такая авария снова доедет до прода.
